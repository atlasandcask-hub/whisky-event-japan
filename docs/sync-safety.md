# WEJ 自動同期の安全停止

Issue #2 対応。イベントは名前・日付ではなく `id` で照合する。
既存IDが1件でも「掲載」候補から消える場合は、IDと理由を表示して終了コード1で停止する。
非掲載への変更も削除として扱う。新規IDを追加して総件数を維持しても回避できない。
例外は `scripts/publication_holds.json` で個別レビューした掲載保留のみ（下記）。

## 公開データの保全

- 公開用説明・画像URL・チケットURLがシートで空なら同じIDの既存値を保持する。
- 説明文の切り詰め・内部メモの自動削除は行わない。
- URLが入力されているのに不正な場合は空文字への置換ではなく停止する。
- 既存JSONの欠落・破損・重複ID、CSVの見出し・列数・重複ID・日付・URLの異常も停止する。
- 同期前に `events.json.backup` を作成し、候補全体の検証後に一時ファイルから原子的に置換する。
- 失敗時は既存JSONを保持する。Actionsはバックアップを30日間のartifactとして保存する。
- Actionsは同時同期を直列化し、テスト・同期・検証が失敗すればコミットへ進まない。

## 内部メモの混入防止

公開項目の許可リストでJSONを組み立て、備考・ステータスなどは公開しない。
公開テキスト中のCanva、WEJ管理ID、GitHub、DB管理記録、作業記録、未確認メモなどを検出すると停止する。
公開用説明と備考の全文一致も停止する。本文を途中で切って通す処理はない。
一般的な「価格未確認」「公式で確認」だけでは内部メモと判定しない。
規則による検知であり、あらゆる自然言語の内部メモを識別できるものではない。
既存HTMLは `publicDescription` をエスケープして表示し、内部備考は参照しない。
HTMLの旧 `publicDescription()` 切り詰め関数は呼ばれておらず、今回サイトは変更しない。

## 実行

```sh
python -m unittest discover -s tests -v
python scripts/sync_events.py --check
python scripts/sync_events.py --dry-run
```

`--check` はローカルJSONの検証のみ。`--dry-run` はシートを取得して照合するがJSONとバックアップを書き換えない。
引数なしの実行は同期を行う。通常の既存Actionsスケジュールは継続する。

## 2026-11-05：掲載100件と意図的な掲載保留

main `0441ff2` の100件を取り込み、100〜103を保持、092を除外した。
103ユニークIDの実シート値のうち掲載100件とID集合が完全一致。

`publication_holds.json` はシートから自動作成しない、PRレビュー対象の承認記録。
IDごとに保留状態、イベント公式URL、延期発表URL、理由、承認日を必須とする。
092はユーザー指示に基づき一般発売延期を保留として記録した。
フェス会場での一部販売を一般発売再開とは扱わない。

- 記録とシートの「保留」・公式URLが一致したIDだけ公開候補から除外可能。
- 既存公開IDならその公式URLも一致必須。除外時はIDをログに表示。
- 承認済みIDでもシート行欠落・URL変更・再掲載・別状態なら停止。
- 他のIDの欠落・非掲載化は引き続き停止。件数補充でも回避不可。
- 保留解除は根拠確認後、シート状態と承認記録の削除を調整してレビューする。
  先にシートだけを変更すると安全停止する。
- 承認ファイルの欠落・破損・不正形式も安全停止する。
- 092がすでに非公開の100件を基準にしても、保留行の存在とURLを毎回検証する。

`events_2026-11-05.json` はmain原文100件、`sheet_public_2026-11-05.csv` は
実シート103行から同期入力列のみを保存。内部備考やIG履歴は含めない。
